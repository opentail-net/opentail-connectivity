# External review, 2026-10-23 (work of 22 and 23 October)

A static review (ChatGPT) of the queue, worker, SQLite vector and web changes. Every finding was checked against the code before
fixing; all of them held. Fixed the same day.

| # | Finding | Checked | What changed |
|---|---|---|---|
| 1 | Worker shutdown can hang: a handler that ignores its token, with no run-time limit, kept `RunAsync` waiting forever | Confirmed: `RunOneAsync` waited only for the run-time limit or a missed heartbeat, never for shutdown | Shutdown now triggers the same grace period; after it the job is handed back ("worker stopped") and the worker returns. Test: `Stopping_finishes_even_when_a_handler_ignores_cancellation_and_no_run_time_limit_is_set` (hung before the fix). |
| 2 | RabbitMQ: changed queue arguments make redeclaring an existing durable queue fail with 406 | Confirmed in principle (no deployment had an old queue). Also found: a queue was marked declared before the declare ran, so after a 406 later calls carried on as if it existed | A 406 becomes an `InvalidOperationException` naming the queue and how to migrate; a queue is marked declared only after success. Migration and the policy option are written up in [messaging and queues](../design/messaging-and-queues.md#upgrading-rabbitmq-queues). Test: `A_queue_declared_with_other_arguments_gives_an_error_that_says_how_to_migrate` (RabbitMQ CI). |
| 3 | A zombie's job was given back at once, freeing its concurrency slot for other workers while the handler still ran | Confirmed: the zombie guard was process-local | The worker keeps renewing the zombie's lease (and so its slot, for every worker sharing the queue) until the handler ends, then gives the job back. Shutdown ends the hold. Test: `A_zombie_keeps_its_key_busy_for_every_worker_sharing_the_queue` (two workers; failed before the fix). |
| 4 | RabbitMQ charged a rate-limit start before the circuit and dead-letter checks | Confirmed for RabbitMQ only; in-memory and SQLite record a start only on admission | Order is now dead-letter check, slot, circuit, rate; a refused rate releases the slot and undoes a probe. Conformance check for every queue: "a job held back by an open circuit uses none of its key's rate limit". |
| 5 | The vector benchmark counted allocations per thread across `await`s | Confirmed | Counted for the whole process (`GC.GetTotalAllocatedBytes(precise: true)`), median of 7. Re-measured: the figures held (6.1 MB, 60.7 MB, 303 MB per search); the design doc says so. |
| 6 | The web connector connected only to the first resolved address | Confirmed | Every address is still checked; then each is tried in order until one connects. Tests for fallback and for the error when none connects. |
| — | `MinScore` accepted NaN and values outside −1..1 | Confirmed | Validated: finite, −1 to 1. |
| — | The heartbeat test failed once on Windows CI | Timing: 80 ms beats against a 200 ms timeout | Timeout widened to 600 ms. |

The reviewer's caveat stands: `MinScore` defaults to null (every hit kept), and the threshold that suits a real embedding model is
not known yet.
